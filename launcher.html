Launcher, dev mode, export

./verilens at the repository root is the one entry point for real projects. It chains the C++ parser and the viewer build so you never run them by hand.

Usage

./verilens <file.v|file.sv|dir> [more inputs...] [options]

  -l, --layout FILE   YAML layout rules
  -t, --top NAME      top module (default: the `// verilens: top` pragma, else the unique root)
  -o, --out FILE      output HTML (default: ./<first input name>.verilens.html)
      --dev           run the Vite dev server with these inputs preloaded instead of building HTML
      --port N        dev server port (default 5173)
      --no-open       do not open a browser
      --rebuild       force rebuilding the core and the viewer bundle
  -h, --help

What it does

  1. Builds gen_ast with CMake if build/core/tools/gen_ast is missing, and runs npm install in packages/web if node_modules is missing.
  2. Runs gen_ast on the inputs (absolute paths, so it works from any directory). Validator warnings are printed; validation errors (exit 2) are reported and the run continues with the structural model.
  3. Default mode: builds the viewer bundle if dist/index.html is missing, embeds the design and the layout file into one HTML with scripts/build-html.mjs, and opens it. The AST JSON is written next to the HTML.
  4. --dev mode: starts the Vite dev server with VERILENS_SESSION_* environment variables; a small Vite middleware serves the parsed design and the YAML at /__verilens/session.json, re-reading both files on every request. The scratch AST goes to packages/web/.verilens/.

Generated *.verilens.html and *.verilens.ast.json files are ignored by git.

Planning loop with --dev

./verilens rtl/ -l layout.yaml --dev
  1. The viewer opens on the top module with your rules applied.
  2. Use the Modules tab to open each module definition and judge its automatic layout.
  3. Edit layout.yaml in your editor; press Reload files in the Layout tab to re-read it. Or edit in the tab and press Apply.
  4. Rejected files list every problem and keep the last valid layout. Relaxed preferred rules show in the diagnostics drawer with the amount.
  5. When satisfied, Export HTML, or run the launcher without --dev for the same file from the command line.

Export HTML

The viewer is built as a single file (scripts and styles inlined). Export HTML clones the running page, embeds the current design and layout text in a <script type="application/json" id="verilens-data"> tag, and downloads it. On load, a page with that tag boots from it instead of the demo. scripts/build-html.mjs does the same from the command line:

cd packages/web && npm run build
node scripts/build-html.mjs my.ast.json [layout.yaml] [--top NAME] -o my.html

Both the gen_ast array and the normalized design JSON are accepted as the first argument. A rejected layout file stops the build with its diagnostics (exit 2).

Opening files in the viewer

Open… in the toolbar accepts *.json (AST or normalized, auto-detected) and *.yaml/*.yml (layout rules, applied immediately). The Samples menu loads the bundled demo in three variants. URL parameters for development: ?sample=auto|layout|conflict and ?focus=top/compute.

Windows

The launcher is a Bash script; use Git Bash or WSL. The two steps it wraps work natively: build\core\tools\gen_ast.exe inputs > design.ast.json, then node packages\web\scripts\build-html.mjs design.ast.json -o design.html after npm run build.
