VeriLens is an interactive RTL schematic viewer. Point it at a Verilog or SystemVerilog project and get a zoomable, hierarchical schematic: modules as boxes you can expand in place, nets you can trace across module boundaries, and a small YAML file to say how things should be arranged.

Whole-project analysis

A C++ core lexes, parses and links every file you give it, resolves instances across files, and emits a structural JSON model. No regular-expression parsing.

Input formats →

Expand without reflow

Each module gets a fixed frame. Clicking [+] renders its contents inside that frame; nothing around it moves, and the camera stays put.

Navigating the viewer →

Layout you can version

A small YAML DSL expresses leftOf, above, alignY, port order and frame sizes per module instance, with required and preferred strengths and clear diagnostics.

Layout DSL →

One command

./verilens rtl/ -l layout.yaml builds what is missing, parses your sources and opens a self-contained HTML file you can send to anyone.

What you get

  • Schematic, not graph soup. Layered left-to-right flow, orthogonal wires, junction dots only where a net really branches, bus widths and net names on the wires, familiar gate symbols, and labelled boxes for everything else.
  • Hierarchy that stays readable. A tree on the left, breadcrumbs on the canvas, [+]/[−] on every instance, and Focus module to open any instance full-size with a Back that restores your previous view.
  • Real connectivity. Clicking a net colors its driver and sinks and follows the net up into the parent and down into expanded children. Nothing is inferred from names; black boxes, constants, unconnected ports and multiply-driven nets are shown as such.
  • Predictable interactions. Nothing on the canvas can be dragged or edited. Pan from the background, zoom at the pointer, fit design or selection. Geometry changes only when you load a design, apply a layout file, or press Re-layout.

The viewer keeps four things strictly apart: the design (what exists), the layout rules (how to arrange it), the computed geometry, and UI state. Layout rules never change connectivity. Read more in Architecture and invariants.

Status

VeriLens is an early, working tool. The parser handles the structural subset of Verilog-2005 and common SystemVerilog (always_ff/always_comb, ANSI ports, parameters, generate regions, gate primitives). It is not a full SystemVerilog front end; see Limits. Layout quality is heuristic and documented as such.
