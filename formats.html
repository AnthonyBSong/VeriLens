Input formats

The viewer accepts the core's AST JSON or a normalized design JSON, plus an optional YAML layout file. This page documents the first two; the layout file has its own page.

From Verilog to the viewer

cmake -S . -B build && cmake --build build
./build/core/tools/gen_ast path/to/project > project.ast.json     # a file, several files or a directory

gen_ast scans directories recursively for .v and .sv, parses every file with its own lexer and parser, links instances across files, runs the connectivity validator, and prints one JSON array of modules. Diagnostics go to stderr so stdout stays clean; validation errors set exit code 2 but the JSON is still complete. Open the file with Open…, or let ./verilens do all of it.

What the core extracts

  • Module declarations: name, source file and line, parameters, ports with direction and width (parametric widths keep their text).
  • Instances: module name, instance name, parameter overrides as {name, value}, and every port connection both as raw text and as a parsed expression tree.
  • Net declarations, continuous assigns with full expression trees, always blocks with sensitivity list and statement tree, gate primitives, generate regions (flattened).
  • A resolved flag per instance: false when the module is not among the inputs (library cells, missing files).
  • // verilens: top comments, attached to the module they precede or sit in.

Normalized design JSON

The viewer's own format, produced by the adapter and accepted directly by Open…. Hand-written or produced by another front end, it goes through the same validation.

{
  "version": 1,
  "top": "top",
  "modules": {
    "top": {
      "name": "top",
      "source": { "file": "demo.sv", "line": 5 },
      "ports": [
        { "name": "clk",  "direction": "input",  "width": 1 },
        { "name": "data", "direction": "output", "width": null, "widthExpr": "W-1:0", "net": "data" }
      ],
      "nets": [ { "id": "clk", "width": 1 }, { "id": "$add_5", "width": null } ],
      "cells": [
        { "id": "compute", "kind": "instance", "module": "compute", "resolved": true,
          "params": { "DEPTH": "4" },
          "connections": {
            "clk":   [ { "net": "clk" } ],
            "b":     [ { "net": "acc", "msb": 15, "lsb": 0 } ],
            "coeff": [ { "const": "12'd0" }, { "net": "coeff_sel" } ],
            "dbg":   []
          } },
        { "id": "$mux_6", "kind": "primitive", "type": "mux",
          "ports": [ { "name": "S", "direction": "input", "width": null },
                     { "name": "1", "direction": "input", "width": null },
                     { "name": "0", "direction": "input", "width": null },
                     { "name": "Y", "direction": "output", "width": null } ],
          "connections": { "S": [{ "net": "mode" }], "1": [{ "net": "sum" }], "0": [{ "net": "pe1_out" }], "Y": [{ "net": "mux_out" }] } }
      ]
    }
  }
}
  • A connection is an ordered list of segments, msb first; several segments form a concatenation; a segment is either a net (optionally sliced with msb/lsb) or a constant.
  • A module port's net is the internal net bound to it (defaults to the port name). This is the only link across a hierarchy boundary; nothing is matched by name.
  • Instances take their port list from the module definition; unresolved instances (resolved: false) list the ports they connect. Primitives list their own ports.
  • Drivers and sinks are derived from directions: outputs and module inputs drive, inputs and module outputs sink, inout counts as both. Undriven and multiply-driven nets are reported, never repaired.
  • Known primitive types get symbols: and nand or nor xor xnor not buf mux add sub mul div mod pow neg eq ne lt le gt ge shl shr sshl sshr process. Anything else is a labelled box.

Limits

  • The core is a structural extractor, not a compiler: no elaboration, no type checking beyond width comparison, no evaluation of parameters or generate conditions.
  • Not supported: interfaces, packages, user-defined types (identifiers of unknown types become implicit nets), functions and tasks (skipped), full SystemVerilog.
  • Always blocks are one cell each; no register or mux inference inside them, no FSM view yet.
  • Struct fields collapse to their base net, so several field assigns look like multiple drivers of one net.
  • Yosys JSON is not supported; the core parser is the ingestion path.
